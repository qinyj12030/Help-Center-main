## 什么是API？

**API** (Application Programming Interface，应用程序编程接口)，你可以把 API 理解成不同系统之间的「数据快递通道」。

从其他平台获取数据到智跃 Zleap 里，API 就是双方提前约定好的 "快递路线"：

- **API 请求地址** = 快递要送达的目的地
- **参数** = 快递面单上的 "备注信息"（告诉对方你要什么类型、什么范围的数据）
- **请求方式（如 GET）** = 快递的 "取件规则"（比如是 "上门取件" 还是 "网点自提"）

填写好上面的信息，数据就能自动从对方系统 "快递" 到智跃 Zleap 里。

---

## 用 API 采集信息的优势

### ✅ 实时新鲜

配置好请求地址后，系统会直接从对方系统拉取最新数据，实时抓取动态数据。

### ⚙️ 自动省力

只要配置好参数和超时时间，系统会定期自动同步数据，不用每天重复手动操作，把人力从 "搬运数据" 里解放出来。

### 🎯 准确少错

系统直接对接传输数据，避免了人工录入时的抄错、漏填问题，数据准确率更高。

### 🔧 灵活定制

通过「添加参数」，你可以根据业务需求定制数据范围，还能选择请求方式，适配不同系统的要求。

## 如何使用接入API作为信息源？

以高德获取天气信息为例

### 步骤一：获取API

1. 打开[高德开放平台官网](https://lbs.amap.com/)，注册 / 登录开发者账号
2. 进入「控制台」→「应用管理」→「创建应用」（命名如 "智跃天气同步"）
3. 应用创建后，点击「添加 Key」，选择「Web 服务 API」类型，提交申请

<Callout type="warn" title="关键提醒">
拿到 API 后，一定要问清 3 件事：

- **是否需要密钥**（token/AppID）？（安全相关，必填）
- **调用频率限制**（比如每分钟最多调用 100 次，避免被拉黑）
- **数据返回格式**（一般是 JSON，确保智跃 Zleap 支持）
</Callout>

### 步骤二：API 配置

#### 1. 进入配置页面

打开智跃 Zleap「信息管理」模块 → 选择「API 接入」→ 进入配置页面。

#### 2. 填写API信息

填写基础配置：「API名称」、「API请求地址」，设置请求方式和超时时间。

![API配置界面](/images/API接入/1.png)

**请求方式说明：**

| 请求方式 | 核心作用 |
|---------|---------|
| **GET** | 拿数据：从对方系统获取信息（不修改数据） |
| **POST** | 发新数据：向对方系统提交新内容（会创建新资源） |
| **PUT** | 全改数据：把某个资源的所有信息全替换成新的 |
| **DELETE** | 删数据：删除某个已有的资源 |
| **PATCH** | 改部分数据：只修改资源里的某几项内容 |

<Callout type="info">
获取信息的话一般就用 **GET**！
</Callout>

#### 3. 添加请求参数

点击「添加参数」，填写 key 等必填与可选的参数。

#### 4. 调试 + 保存

1. 点击配置页「调试」按钮，系统会发送请求
2. 若返回「测试成功」，说明配置成功
3. 调试通过后，点击「保存」，广州天气信息源创建完成

![API调试成功](/images/API接入/2.png)

### 步骤三：提交信息

填写「信息名称」等必要信息和选填信息后，点击「提交信息」。

![提交信息界面](/images/API接入/3.png)

<Callout type="info">
接下来，您就可以使用创建的信息源创建报告助手、搜索助手或问答助手啦！
</Callout>

信息源创建成功后，您可以在信息源列表中查看详细信息：

![信息源详情](/images/API接入/4.png)

## FAQs

### 为什么要设置超时时间？

你发了一个 "取件请求"（API 请求），并约定最多等 30 秒。如果快递员（对方系统）30 秒内没把数据送过来，你就会判定这次取件失败，不再继续等下去。

#### 🚫 避免系统卡住

如果对方系统出现故障、网络中断，没有超时时间的话，你的系统可能会无期限等待，导致界面卡住、资源浪费。

#### ⏱️ 保证体验与效率

合理的超时时间（如 30 秒）能让系统及时判定请求失败，你可以快速排查问题（比如检查网络、联系对方管理员），而不是让用户一直干等。

#### ⚖️ 平衡稳定性和成功率

- 时间太短（如 5 秒）可能因网络波动误判正常请求
- 时间太长（如 120 秒）又会拖慢系统响应
- 30 秒是通用的默认值，但你可以根据实际场景调整

<Callout type="info" title="超时时间设置建议">
- 如果对方系统响应较慢（比如需要查询大量历史数据），可以适当调长超时时间（如 60 秒）
- 如果是实时性要求高的请求（如支付、订单接口），建议调短超时时间（如 10-15 秒），避免用户等待过久
</Callout>
